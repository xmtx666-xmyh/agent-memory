# 判定语义与已知局限（引用前必读）

> 本文出现的**实体名与项目路径都是本机示例**（每台机器不同）；换机器请先用 `am.ps1 topics --top 20` 查本机实际有哪些实体。


本文件是 `premises` / `inject` 结果的口径说明。**误读这些口径会把仍有效的经验误杀**，
那与本技能的目（少走弯路）正好相反。

## 一、三档判定的准确含义

| 判定 | 判据 | 该怎么说 |
|---|---|---|
| 🟢 `alive` | 引用路径当前存在 | "前提仍然成立" |
| 🟡 `dead_with_successor` | 路径不存在，但**它所属的实体仍有存活目录** | "**项目已改名**，旧路径应换算成 X；结论可能仍有效" |
| 🔴 `dead_no_successor` | 路径不存在，且该实体已无任何存活目录 | "**真失效**，勿照做" |
| ⚪ `unverified` | 无可验证前提／非项目资产（系统目录、临时目录、乱码伪路径） | "**无法判定是否过时**，只能标未验证" |

⚠️ **最常见的误读**：把 🟡 说成"失效"。
项目改名（`F:\demo-wiki` → `F:\demo-base`）意味着前提**换了名字活着**，
直接标"勿照做"会把仍有效的经验错误劝阻 —— 实测这一条错了会误伤 40 条仍有效的结论。

## 二、后继目录的排序

`inject` 里"已迁移至 X"，X 按**最后被工具调用碰到的时间**倒序取第一个，
不是字母序。实测按字母序会把 `f:\demo-wiki2` 当正确答案，而真正在用的是 `f:\demo-base`。

## 三、97% 的结论无法机械判定

实测项目「demo-kb」3173 条结论：**3098 条（97.6%）没有任何可验证前提**（纯观点/描述）。
所以：

- 本技能**只能**自动判定 1~2% 的结论；
- 其余一律标 ⚪ 未验证，**引用时要说明"未验证"**，不要讲成硬结论；
- 不要因为"技能没报失效"就认为结论一定有效。

## 四、注入块的价值边界（实测 A/B）

| agent 能力 | 旧路径的后果 | 注入的价值 |
|---|---|---|
| 弱（本地 9B） | **答错**（0/3 正确） | **救错误** |
| 强（Codex） | 全答对，但工具调用 **16 次 vs 2 次**（−87.5%） | **省探索 + 省信任成本** |

且价值**取决于 cwd 是否已在正确项目**：
cwd 已在正确项目 → 旧路径几乎零成本；cwd 不在 → 成本涨 8 倍。

⇒ 这个块在**跨 agent 续接、被中途唤起**时最值钱。

## 五、`check_at` 会过期

注入块是**生成时刻的快照**。若目录/端口之后又变，块就过期。
所以：

- 块头必须带 `check_at`，引用时看一眼日期；
- 单跑 `inject` 只要约 **1 秒**（实测 0.9 s），所以**每次会话开始时现算**即可，
  不必等定时任务；`ingest`+`topics`（约 40~50 秒）才适合每天跑一次
  （见 `@scripts/refresh.ps1`，它读 `index/targets.json` 并走 `_resolve.ps1`）；
- **不要把带时间戳的内容写进系统提示**（会破坏前缀缓存）。

## 六、不做的事（明确的边界）

- **不自动连"v1→v2→v3"演进链**：实测同一决策键出现多值 = **0 条**，连不起来；硬做只会造出假链。
- **不做级联失效**：那 3% 有前提的结论，其前提是**路径/端口/模型（外部世界对象）**，不是别的结论，级联边型不存在。
- **不删除"错误思路"**：那是最高价值资产（避免重试），只标状态不删除。
- **不改写原文**：会话标题里的旧项目名是历史原文，只改**归属标签**。
