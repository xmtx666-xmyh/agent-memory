# B 验证：注入「迁移提示」到底有没有价值？

> 2026-11-03 ｜ 前置：`docs/staleness-design.md`（前提校验 P0）。
> 本文回答一个问题：**把那 40 条 🟡 + 2 条 🔴 注入给新会话，是真省 token 还是自我安慰？**

## 验证状态

**已实测**：幽灵路径的"真操作"次数、改名时点、迁移后可解析率（全部基于 618 会话的工具调用记录）。
**未实测**：真实 agent 的 token 耗时 A/B（要跑 agent，本轮未做）——所以本文证明的是**价值前提成立**，不是**省 token 的量化收益**。

## 一、结论先说

**注入有真实价值，而且比预想的更紧迫**——因为改名就发生在 **2026-10-27（6 天前）**，
而 **177 个会话的工具调用**指向那个已经不存在的目录。

## 二、关键数据

### 2.1 幽灵路径不是"陈年老账"，是上周的

| 目录 | 状态 | 被工具调用碰过的会话 | 首次 | 末次 |
|---|---|---|---|---|
| `f:\demo-wiki` | **不存在** | **177** | 2026-09-13 | **2026-10-30** |
| `f:\demo-base` | 存在 | 12 | **2026-10-27** | 2026-11-01 |
| `f:\demo-next` | 存在 | 2 | 2026-10-18 | 2026-11-01 |

**切换时点 ≈ 2026-10-27**：旧路径最后使用 10-30，新路径首次出现 10-27。
按天统计：10-23 前只有旧路径；11-01 起只有新路径。

### 2.2 那 177 个会话是真的在读写，不是"提到"

路径出现在工具参数哪个字段（抽样 150 个会话）：

| 字段 | 次数 | 性质 |
|---|---|---|
| `file_path`（read/write） | **5556** | **真操作文件** |
| `path`（glob/grep） | **1640** | **真检索目录** |
| `command`（shell 命令里） | 1384 | 真执行 |
| 其它（content/prompt/message） | ~400 | 讨论时提到 |

⇒ **绝大多数是真去读写 `F:\demo-wiki\...`**，不是引用文献。这些会话的结论里若带着该路径，
新 agent 照着做就会**打开一个不存在的目录**。

### 2.3 迁移后可解析率：多数能接上

把原路径的后半段接到新目录下，**大部分能找到对应文件**：

```
F:\demo-wiki\server\api\wiki.py        →  f:\demo-base\server\api\wiki.py        ✅
F:\demo-wiki\AGENTS.md                 →  f:\demo-base\AGENTS.md                 ✅
F:\demo-wiki\tools\eval_golden_v4.py   →  f:\demo-base\tools\eval_golden_v4.py   ✅
F:\demo-system\agents\master.py         →  ❌ 后继目录里也没有（文件也改名了）
F:\demo-wiki\.pytest_tmp               →  ❌ 临时目录，本就不该引用
```

→ **注入"迁移至 X"是可用的**（多数能直接定位），但**不能保证**（少数文件也改名了）。

## 三、过程中修掉一个会让注入直接误导的 bug

`live_dirs_by_entity` 原按**字母序**返回后继目录，导致提示写成
「已迁移至 `f:\demo-next`, `f:\demo-wiki2`」——而正确答案是 **`f:\demo-base`**（最近还在用的那个）。

修法：按**最后被工具调用碰过的时间**倒序。修后提示为
「已迁移至 `f:\demo-base`, `f:\demo-next`」。

**这条很关键**：注入一句错的后继，比不注入更糟（把 agent 引到也找不到的地方）。

## 四、注入优先级（按实测价值排）

| 优先级 | 内容 | 条数 | 依据 |
|---|---|---|---|
| **高** | 🟡 迁移提示（含正确后继） | 40 | 改名 6 天、177 会话的操作路径失效、多数可解析 |
| 中 | 🔴 真失效（2 条） | 2 | 都是真实但不关键（备份盘、已卸载软件） |
| 低 | ⚪ 未验证 3098 条 | 3098 | 无可验证前提，注入只会占上下文 |

## 五、诚实的天花板

本文证明的是**价值前提**：**有大量仍在使用的结论指向一个已改名的目录**。
**没有**证明"注入后 agent 真的少走了弯路、少烧了 token"——那需要真跑 agent 的 A/B：

- 基线：给 agent 一个依赖旧结论的任务（如"按 10-23 的结论修 `F:\demo-wiki\...`"）
- 实验：同一任务 + 注入迁移提示
- 看 `步数 / prompt token / 是否一次找对文件`

本地 Ollama 免费可跑，但**9B 的工具调用可靠性**未知（见 `tools/bench_local_llm2.py`：
thinking 默认开会导致空输出，必须 `think=false`），所以这个 A/B 要单独设计。

## 六、遗留

1. **token 收益未量化**（需 agent A/B）。
2. 迁移"不可解析"的那部分（文件也改名）注入措辞应更软："项目已迁至 X，同名文件可能也改名，需确认"。
3. `f:\demo-kb`（中文名目录）与 `f:\demo-base` 的关系未查——可能是同一项目的两个工作副本。
