# 演变时间线（第二阶段 B）：话题的结论按时间排开 + 冲突检测

> 2026-11-03 ｜ 前置：`docs/topics-a.md`（话题归并）。
> 本文记录 B 的落地、真实抽取样例、以及**明确的局限**。

## 验证状态

**已实测**：2 个话题跑通（`demo-kb × 检索与排序` 82 会话 / `PageIndex` 9 会话）；
10 条契约测试；真实输出已落 `docs/example-timeline-pageindex.md`。
**未验证 / 不做**：不接 LLM（理由见 §一）；冲突检测只覆盖 `键=值` 写法（见 §四）；
没有"哪条结论最终生效"的自动裁决。

## 一、为什么不接 LLM

1. LLM 摘要**无法复核**，容易产出"看起来对"的结论 —— 本仓纪律要求可复盘；
2. 先用规则把**结论句定位**做出来（只需匹配），候选错了能一眼看出；
3. 后续若要用 LLM 判断"哪条被推翻"，也只在**已定位的候选**上做，成本与风险都可控。

## 二、抽取规则（基于实测标记词分布）

探针：`tools/probe_conclusion_markers.py`（在真实话题上统计标记词命中）。
实测结论：`修复` 命中 251 次但绝大多数是「Bug 修复」菜单项；`确认` 多为动作过程 →
**这两个词不认**。只认两类：

| 类型 | 规则 | 例 |
|---|---|---|
| A 标题锚定 | 行首带 `结论/决定/根因/最终/已验证/已修复/定稿/定案/判定` | `### 结论` |
| B 强决策短语 | `改为/改成/改用/不再用/废弃/回退到/验证通过/实测/判定为/替换为` | `3 处调用改为 .get("ok")` |

同时剥掉：表格行（`|` ≥2）、代码围栏、markdown 前缀（`> **`）、`**` 残留、短于 12 字的行。

## 三、状态判定（防"把废弃方案当现状"）

| 状态 | 判据 | 含义 |
|---|---|---|
| `superseded_candidate` | 废弃/不再用/推翻/作废/改回/回退到旧/恢复旧/弃用 | 可能推翻前面的结论 |
| `experiment` | 实验/试验/临时方案/A-B/对比一下/先这样 | 试验性，不是现状 |
| `verified` | 实测/验证通过/已验/跑通 | 有实测支撑 |
| `decision` | 其余 | 默认 |

⚠️ **踩坑**：裸「回退」不能算推翻 —— 实测代码语境里「回退到 PyMuPDF」是**降级路径**，
不是"推翻上个决定"（PageIndex 话题里两条都被误标成 superseded，已修）。

## 五、冲突检测：能做什么、不能做什么

**做法**：从结论句里抽 `键=值` 对（键必须是参数名、或值带单位），同一话题下同键多值 → 冲突，
并列出各值出现的时间。

**实测噪音与修法**（不修就是负价值）：

| 噪音 | 根因 | 修法 |
|---|---|---|
| `py` 键 40 个不同值 | `search_service.py:144` 被抽成 `py=144` | 文件后缀当键直接拒 |
| `技术选型` 一锅炖 | 把所有技术词（ollama/streamlit/chroma…）塞进一个键 | **删掉枚举冲突**，只留数值参数 |
| `结论 = 14.2` | 泛词当键 | 键黑名单（结论/最终/根因…） |
| 无参数味的键 | 任意"词=数"都算冲突 | 键须含参数提示词，或值带单位 |

**明确局限**：
- 只覆盖 `键=值` / `键：值` / `键改为值` 写法；**`60 → 15`、`从 60 改成 15` 这类抓不到**
  （实测精排候选数 60→15 那次改动就没被检出）。
- 不做"哪条最终生效"的裁决 —— 只呈现冲突，由人判断。
- 同一键的不同值若语义相同（如 `60` 与 `60条`）会被算成冲突。

## 六、用法

```powershell

.\venv\Scripts\python.exe cli.py timeline "demo-kb" "检索与排序" --per 3

# 落盘 markdown
.\venv\Scripts\python.exe cli.py timeline PageIndex --per 2 --out docs/timeline-pageindex.md

# 任意实体（不限意图）
.\venv\Scripts\python.exe cli.py timeline "示例客户项目(DEMO2021)"
```

## 八、遗留

1. **箭头写法的冲突抓不到**（`60 → 15`），需要扩一条正则。
2. **没有"结论 → 会话 → 原文位置"的跳转**（现在只给标题与日期，回查要自己用 `cli.py search`）。
3. **同一话题下结论可能很多**（51 个），缺"按参数聚合"的视图。
4. 未验证在**业务项目**话题上的效果（如 `示例街道A`，会话少、结论多为数值）。
